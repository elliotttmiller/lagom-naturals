# Manual Review Protocol

Use this after `audit.py` produces candidate evidence.

## Step 1 — Resolve the entity

A candidate should only be treated as Lagom when one or more strong identifiers align:

- exact legal name: `LAGOM NATURALS LLC`;
- DBA: `LAGOM NATURALS`;
- exact North Loop address;
- official application/license number later tied to Lagom;
- public ownership/control data that resolves the entity.

A fuzzy name match alone is not sufficient.

## Step 2 — Assign evidentiary weight

### Tier A — dispositive primary evidence
Examples:
- OCM license-holder dataset showing Lagom and an issued license;
- OCM applicant-level response showing explicit current status;
- OCM decision/approval/denial tied to a Lagom application number.

### Tier B — corroborating primary evidence
Examples:
- Minneapolis local cannabis retail registration;
- Secretary of State entity/DBA record;
- Revenue cannabis-related record;
- MDA hemp license record.

These can establish identity or another regulatory relationship but **do not substitute for an adult-use OCM license record**.

### Tier C — contextual
Non-government sources are excluded from this audit package by design. They can be used later only as secondary corroboration.

## Step 3 — Apply classification

### issued license
Use only when an authoritative OCM record explicitly establishes issuance.

### applicant
Use when OCM public data confirms an application exists but gives no stronger status.

### qualified applicant
Use when OCM explicitly says initial application requirements were met / qualified status reached.

### preliminary approval
Use only for explicit preliminary approval.

### pending
Use for under-review/awaiting required action/final-plans/pre-license-inspection status.

### denied
Use for official denial.

### withdrawn
Use for official withdrawal.

### historical
Use for authoritative records that establish identity or past regulatory context without proving current licensing status.

### unrelated
Use for false positives.

### unresolved
Use when potentially relevant evidence cannot yet be resolved.

## Step 4 — Currentness check

Always compare:
- publication/update date;
- status date;
- later superseding record;
- whether the record is a snapshot or historical archive.

A June 2026 tax posting, for example, is evidence of that June 2026 event, not automatic evidence of current September 2026 status.

## Step 5 — Final conclusion language

Permitted conclusion examples:

**Verified issued license**
"OCM's [date] license-holder dataset identifies LAGOM NATURALS LLC as the holder of [license type], license [number]."

**Verified in process**
"OCM public applicant data identifies LAGOM NATURALS LLC application [number] as [qualified/preliminarily approved/pending] as of [date]. No final issued license was located in the current license-holder dataset."

**No public match located**
"No matching Lagom record was located in the official datasets reviewed. This is not treated as proof that no application exists; applicant-level data not publicly downloadable must be resolved through OCM's public-data process."
